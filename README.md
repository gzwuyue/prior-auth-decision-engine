# Prior Authorization Decision Engine (Claude demo)

A small, working reference design for **LLM-assisted prior authorization** in health insurance.
A faxed request comes in as a scanned PDF; Claude (or Tesseract OCR) reads it; Claude extracts evidence
against each coverage criterion; plain, auditable rules make the decision; and **the system never
auto-denies**: anything that looks like a denial is routed to a licensed clinician.

> The 12 evaluation requests and all coverage policies are **synthetic**; the policies are simplified
> illustrations, not real medical policy. Three additional notes are real, publicly shared transcription
> samples from [MTSamples](https://www.mtsamples.com), used unlabeled for demonstration
> (see `data/public_notes_NOTICE.md`). No PHI is included.

## Why this design

Prior authorization is a high-volume, high-stakes workflow. In production at a large payer, the
pattern that earns trust from clinicians, compliance and regulators is:

1. **LLM for reading, code for deciding.** The model's job is evidence extraction: messy notes in,
   structured findings out. The coverage decision is deterministic code anyone can audit.
2. **Every claim cites the chart.** Each finding must quote the note verbatim. A guardrail checks the
   quote exists; if not, the finding is downgraded to "not documented" so it can never drive an approval.
3. **Automate the yes, route the no.** Clear approvals are automated for speed; missing information
   triggers a request to the provider; potential denials go to a clinician.
4. **Evals before rollout.** A gold-labeled test set measures accuracy and, above all, **unsafe
   approvals**: the number that has to be zero before anything ships.

```mermaid
flowchart LR
    F[Faxed PA request<br/>image-only PDF] --> O[Intake: Claude vision<br/>or Tesseract OCR]
    O --> R{CPT/HCPCS code<br/>matches a policy?}
    R -- no --> M[MANUAL INTAKE]
    R -- yes --> A[Structured request<br/>+ clinical note]
    A --> B[Claude evidence extraction<br/>structured outputs, JSON schema]
    P[(Coverage policy<br/>criteria)] --> B
    B --> G{Grounding check<br/>quote found in note?}
    G -- no --> N[Downgrade to<br/>NOT_DOCUMENTED]
    G -- yes --> D[Deterministic<br/>decision rules]
    N --> D
    D -->|all criteria met<br/>or red-flag override| AP[APPROVE]
    D -->|documentation gap| RI[REQUEST INFO<br/>from provider]
    D -->|criterion not met| CR[CLINICIAN REVIEW<br/>no auto-denial]
    D --> L[(JSON audit record)]
```

## What's in the repo

| Path | What it does |
| --- | --- |
| `data/policies.json` | 3 illustrative policies: lumbar MRI, GLP-1 for weight management, total knee replacement |
| `data/requests.jsonl` | 12 synthetic requests with gold labels per criterion and per decision (generated by `data/make_cases.py`) |
| `data/public_notes.jsonl` | 3 real MTSamples transcriptions (knee osteoarthritis, low back pain, weight management), unlabeled |
| `data/scans/` | Every request rendered as a faxed, image-only PDF (no text layer) by `data/make_scans.py` |
| `pa_engine/intake.py` | `ClaudeDocumentReader` (PDF vision) and `TesseractReader` (offline OCR), plus CPT routing with OCR-error correction |
| `pa_engine/extractors.py` | `ClaudeExtractor` (Anthropic SDK, structured outputs) and `KeywordExtractor` (regex baseline) |
| `pa_engine/decision.py` | The decision rules, about 20 lines of auditable code |
| `pa_engine/engine.py` | Orchestration plus a JSON audit record per request |
| `eval/run_eval.py` | Accuracy, unsafe approvals, missed approvals, ungrounded evidence; in scan mode, OCR similarity and routing accuracy |
| `tests/` | 15 unit tests with mocked Claude clients (no API key needed); a real Tesseract test runs when it is installed |

## Quick start

```bash
git clone https://github.com/gzwuyue/prior-auth-decision-engine.git
cd prior-auth-decision-engine
python -m venv .venv && source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -r requirements.txt

# Runs offline, no API key: the keyword baseline
python -m pa_engine.cli --all --offline
python -m eval.run_eval --extractor keyword

# With Claude: set your API key first
export ANTHROPIC_API_KEY=sk-ant-...                     # macOS / Linux
# $env:ANTHROPIC_API_KEY = "sk-ant-..."                 # Windows PowerShell
python -m pa_engine.cli PA-2002 PA-2003
python -m eval.run_eval --extractor claude

# From faxed PDFs: Claude reads the scan itself (no OCR install needed)
python -m pa_engine.cli --scan data/scans/PA-2002.pdf data/scans/MTS-2085.pdf
python -m eval.run_eval --extractor claude --from-scan --ocr claude

pytest -q
```

**Optional: offline OCR with Tesseract.** Install the Tesseract binary
([Windows installer](https://github.com/UB-Mannheim/tesseract/wiki); macOS `brew install tesseract`;
Ubuntu `sudo apt install tesseract-ocr`), then:

```bash
pip install -r requirements-ocr.txt
python -m pa_engine.cli --scan data/scans/PA-2002.pdf --ocr tesseract --offline
python -m eval.run_eval --extractor keyword --from-scan --ocr tesseract
python data/make_scans.py            # regenerate the fax PDFs
```

Set `PA_MODEL` to try a different model (default `claude-sonnet-5-5`).

## Results

The test set is deliberately small but tricky: negation ("no hypertension"), family history
("mother was diagnosed with medullary thyroid carcinoma"), timing ("started 2 weeks ago"), and
therapy that was ordered but never done.

| Input | Extractor | Decision accuracy | Criterion accuracy | Unsafe approvals | OCR similarity |
| --- | --- | --- | --- | --- | --- |
| Text notes | Keyword baseline | 83% | 82% | **1** | n/a |
| Faxed PDFs, Tesseract OCR | Keyword baseline | 83% | 82% | **1** | 99.9% |
| Text notes | Claude (`claude-sonnet-5-5`) | _run `--extractor claude`_ | | | n/a |
| Faxed PDFs, Claude vision | Claude (`claude-sonnet-5-5`) | _run `--extractor claude --from-scan --ocr claude`_ | | | |

The baseline's unsafe approval is PA-2002: the note says *"BMI 28.1, **no** hypertension, diabetes,
dyslipidemia or sleep apnea"*, and keyword matching reads the comorbidities as present. Full
per-case results are written to `eval/results/`.

**What OCR taught us.** Even on clean synthetic faxes, Tesseract misread the HCPCS code `J3490` as
`33490` and picked up speckle noise as punctuation (`CPT/HCPCS:.`, `Clinical -notes:`). The intake step
validates codes against the policy code set, corrects a code only when exactly one known code is a
single character away (and logs the correction in the audit record), and sends anything else to
manual intake rather than guessing.

## Taking this toward production

What a real deployment would add, roughly in order:

- **Document intake at scale:** multi-document fax packets, page classification (cover sheet,
  clinical notes, imaging report), and confidence thresholds that route low-quality scans to humans.
- **Integration:** FHIR-based intake (aligned with the CMS prior-authorization API requirements),
  utilization-management system write-back, and member and provider notifications.
- **Retrieval:** pull the relevant policy version and the full chart (labs, imaging reports) rather than a single note.
- **Evals at scale:** hundreds of clinician-labeled cases per policy, criterion-level error analysis,
  and regression runs on every prompt or model change.
- **Governance:** model risk review, PHI handling and zero-data-retention terms, bias monitoring
  across member groups, and human oversight metrics such as clinician override rates.
- **Monitoring:** drift in approval rates by policy and provider, latency, and cost per review.
